FinTrust Digital Bank — Data Analytics Project

Project Overview

As part of the AnalystLab Africa Experience Lab, I worked on a data analytics project focused on understanding transaction performance, customer activity, and transaction-review patterns for a simulated digital bank, FinTrust.

I used SQL, Python, and Power BI to explore the dataset, validate data quality, identify business insights, and present the results through an interactive dashboard.

Objectives

* Assess transaction performance and success rates.
* Explore transaction trends across months, channels, transaction types, and customer segments.
* Validate data quality and consistency.
* Examine patterns in the supplied risk-review indicator.
* Translate analytical findings into practical business recommendations.

Tools and Technologies

* SQL (SQLite): data exploration, aggregation, and validation.
* Python: data cleaning, exploratory data analysis, and timestamp correction.
* Power BI: interactive dashboards and business performance reporting.

Key Findings

* The dataset contains 1,500 customers and 12,000 transactions.
* Total transaction value was ₦560,477,354.85.
* The overall transaction success rate was 90.47%.
* March recorded the highest monthly transaction value in the analysis period.
* Mobile App recorded the highest transaction volume among the available channels, with 5,102 transactions.
* The supplied risk-review indicator varied across transaction types, with transfers showing the highest proportion of flagged records.

Data Quality and Validation

I performed SQL validation checks and reviewed the results against my Python analysis. I checked for duplicate identifiers, unmatched customer records, invalid transaction amounts, missing values, and timestamp parsing issues.

An explicit timestamp format was used to correct parsing problems and ensure that all 12,000 transaction timestamps were interpreted consistently.

Dashboard

The Power BI report includes business performance metrics, monthly transaction trends, channel and segment comparisons, transaction-review patterns, and customer-level drill-through analysis.

Dashboard screenshots and the report file will be included where sharing is permitted.

Important Limitations

This project uses a synthetic educational dataset covering January to March 2026. The supplied review indicator is not confirmed fraud, and the findings should not be interpreted as proof of fraud, customer profitability, or causation.

Project Deliverables

* Final project report
* Supporting screenshots and validation evidence

Conclusion

This project helped me practise the end-to-end data analytics workflow, from data quality checks and exploratory analysis to dashboard development and communicating findings in a business context.
